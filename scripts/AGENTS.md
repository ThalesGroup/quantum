# scripts/ — tooling

Zero-dependency Node (>= 22) except `validate.mjs` and `specs-bridge.mjs`, which use Ajv for
JSON Schema. The token pipeline (`lib/dtcg.mjs`, `build-tokens.mjs`) stays dependency-free.

## What validate.mjs checks

- Tokens: all aliases resolve, no cycles, tier discipline (component → semantic → raw), no duplicate paths.
- Modes: exactly one default mode (no overlay); every other mode overrides existing paths of modal tiers (semantic) only, keeps their `$type`, references raw tokens only, and never a token a platform overlay also overrides; `scheme` is `light` or `dark`. Warns on a mode that overrides nothing.
- Platform overlays: every overridden path exists in an overridable tier (raw, semantic), keeps its `$type`, and its references respect the tier rules; overlay ids exist in `packages/components/specs/platforms.json`.
- Platform registry: ids and inputs equal the schema enums; each platform's `sources` are trusted publishers.
- Specs: schema; changelog has an entry for the current version, newest first; first part is `container`; unique ids; `default` state present; `bindsTo`/`affects`/`property` point at existing ids; part `properties` only on repeatable parts, `visibleIn` and state `parts` name declared states and parts, a `list` property holds repeatable parts; example props use known properties and options, and every entry of a list prop uses its part's instance properties; decision log (unique ids, newest first, versions in the changelog, consistent supersession, token paths that match for every decision not superseded, sources for accessibility decisions); `tokens.source`/`prefix` and `implementations.web.*` paths follow the naming convention.
- Tokens ↔ spec: every token's part exists; state segments are declared; warns on options/states/parts without tokens, except parts that are another component (`component`) and the parts inside them, and options of properties affecting only such parts (they are forwarded to that component).
- Which token applies (`lib/token-map.mjs`): errors on two tokens of a slot that tie for one configuration; warns on a token active in no configuration, on a property without a kind, and on an option segment that reads as a key because its property does not affect the part.
- Accessibility registry: role profiles cite trusted sources and existing WCAG 2.2 criteria.
- Accessibility contract (`lib/a11y.mjs`): every name, keyboard and guideline statement (and every decision with `refs`) cites at least one source; references use trusted URLs; `wcag:` refs exist and belong to WCAG 2.2; the role has a profile and the spec meets it (ARIA role, name, keys, `focus-visible` state, required criteria cited). Uncited references warn.
- Docs: file exists, frontmatter `component:` matches, has a title, has an Accessibility section linking only trusted sources, with every linked WCAG criterion cited by the spec; a `###` sub-heading naming a platform uses the registry's exact name.
- Platform scope: states and examples without `web` in `platforms` are skipped by the CSS and template checks (warned).
- CSS: `:focus-visible` for focusable roles; the native pseudo-class next to every forced state; `prefers-reduced-motion` override when it transitions or animates.
- CSS: exists, defines the root selector, uses only generated `--<id>-*` variables (errors on unknown ones, warns on unused ones and on literals), has a `[data-state="<state>"]` selector for every non-default state, a `[data-<prop>="<option>"]` selector for every non-default enum option mapped to a data attribute, and for every non-default option of an instance enum property of a part (`data-<property>` on each instance).
- Template: imports, exports `render`, renders every example with the root class, renders required parts; the root is `implementations.web.element`; the element carrying the role (the root, or the `implementations.web.rolePart` part inside a wrapper root) does so natively (role profile `web.elements`) or through `role`, carries `role="<ariaRole>"` when the profile says `web.explicitRole`, and exposes its state with one of the profile's `web.stateAttributes` when it lists some (a `summary` is exempt: its state is its parent `details`' `open` attribute); boolean props mapped to native attributes render them; decorative parts carry `aria-hidden="true"`; roles that need a name get one on the element carrying the role (text outside `aria-hidden`, `aria-label`/`aria-labelledby`, or a `label` element whose `for` names its id; a void element such as `input` has no content of its own). Part selectors are matched by the first class of their last compound.
- Orphans: token files, docs, web directories without a spec; `packages/components/src/index.css` imports `fonts.css` and every component; the generated `packages/tokens/dist/css/index.css` exists and imports every component's token file (run `pnpm tokens:build` otherwise).
- Docs site (`lib/site-check.mjs`): `apps/docs/src/**/*.css` and `<style>` blocks read semantic tokens only (errors on literal colors, literal typography, border widths, radii and outline widths, raw or component tokens, unknown variables; `--site-*`, `--ca-*`, `--_*`, `--swatch` are the site's own); every native element of `apps/docs/src/**/*.astro` that a component covers (same element and ARIA role as the element carrying the component's role: the root, or the `rolePart`'s element found by rendering the template) carries the component's root class or the role part's class. Only control roles are covered (`COVERING_ROLES`: button, link, checkbox, radio, switch, textbox, searchbox, spinbutton, slider, combobox, listbox, option, progressbar, meter): a landmark or container component (Breadcrumb's `nav`, Card's `div`) does not claim every element with its role.
- Foundations (`packages/components/specs/foundations/*.spec.json`, schema `foundation.schema.json`): file name and id (not a component id), changelog and decision log as for components, citations (`checkCitations`: guidelines, decisions and contrast refs), owned tokens are semantic, rule tokens exist and are owned, specimens (unique ids, patterns matching raw or semantic tokens, `$type`s the display draws; the display enum equals `DISPLAYS`), every `contrast[]` pair with a `minimum` at or above it in every platform × mode (over each surface of `on`; a requirement with `knownIssue`, a short description of the known problem, reports its failures as warnings naming it, and fails once every pair passes so the marker is removed), every raw and semantic token owned or presented by a foundation (warning), `appliesTo` (every focusable or every component aliases each exact owned path), examples name a component, its properties, options and declared states, and render, or show a code sample (`source`) that exists in `packages/components/specs/foundations/<id>/` (a sample file no example shows warns); `apps/docs/content/foundations/<id>.md` exists with `foundation: <id>`, a title, a sourced Accessibility section consistent with the spec and exact platform sub-headings; no docs page without a foundation.
- Screens (`lib/screens.mjs`, `apps/docs/screens/AGENTS.md`): `sections.json`, every source's `source.json` and licence file, every screen's `meta` and rendered HTML (see the library), no hand-written `ds-*` class in `apps/docs/screens/**/*.mjs`; `apps/docs/screens/screens.css` follows the docs site's CSS rules with its own `--scr-*` variables (`checkSiteCss` with `own`) and never selects a `ds-*` class; every native control of a screen that a component covers is that component (`checkSiteMarkup` with `parts`: a control carrying a component's part class, a Dropdown item, is its own markup). A section without a screen warns.
- Mirrored components (`lib/mirrors.mjs`): each `MIRRORS` entry names two existing components; every token of the mirror resolves to the value of its counterpart in the original (a path prefix of `paths` mapped, any other path the same) in every platform × mode, and every token of the original has a counterpart unless `ignore` lists it. An error names the first context where the values differ.
- Fonts: `packages/components/src/fonts.css` loads the primary family of every font-family token holding a literal value (generic families excepted; aliases are covered by the token they point to).

## What specs-bridge.mjs check checks

For every spec: the export validates against the pinned Specs schema, and importing the export
with its sidecar gives back the exact spec and the exact flattened tokens (path, value, type,
description, extensions). It prints, per component, how many tokens became Specs styles and which
properties stayed sidecar-only. Errors mean the mapping needs work, not the spec.

A `list` property (menu items) has no Specs prop configuration: its values in examples travel in
the sidecar (`examples.<id>.listProps`), and the tokens of the parts it repeats, and of their
children, are sidecar residue (a Specs prop configures the component, not one instance). The
state prop keeps the spec order of every state in `io.quantum.order`.

Token paths are read positionally (`<option>…<state>`): each enum property takes at most one
segment, and a segment whose property is already set is read as the (single) state. That is how
an option value equal to a state id (the scaffold's variant `default`) stays unambiguous.

## Extending

- New DTCG type → `formatScalar` in `lib/dtcg.mjs` + a test.
- A component that must render the same as another one → an entry in `MIRRORS` (`lib/mirrors.mjs`) and a decision in its spec; validate compares the tokens, impact links every change of the original to it.
- New cross-check → `validate.mjs`; keep the `error`/`warn` split: an error must be something an agent can fix mechanically.
- Modes → `packages/tokens/tokens.config.json` `modes` + `packages/tokens/src/modes/<id>/`; no code change. The web contexts (`css.modes`) are emitted by `modeContexts` in `lib/dtcg.mjs`; a mode without a `scheme` gets a `[data-theme]` rule but no `auto` preference.
- A token property that Specs can express (new part role or CSS property) → `STYLE_MAP` in
  `lib/specs-bridge.mjs` + a test. Until then it travels in the sidecar and nothing fails.
